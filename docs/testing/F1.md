# F1 test steps: foundation, auth, profile

Feature: Next.js app, Bangla and English, sign up with email or Google, log out, profile, seek or host mode.
Done when (PROJECT_PLAN.md section 9): a teammate opens the live link on a phone, switches to English, signs up with Google, and edits their profile.

## Before you start
- `.env.local` has the dev project's URL and publishable key (`.env.example` lists them).
- The F1 migration has been run on the dev project (SETUP.md 8.1).
- Supabase **Redirect URLs** include `http://localhost:3000/**` (SETUP.md 3.4).
- For email sign-up: either **Confirm email** is off in dev, or custom SMTP works (SETUP.md 6).
- Run `npm install` then `npm run dev`, and open http://localhost:3000.
- For phone checks use Chrome DevTools device mode at 360px wide, then a real phone on the Vercel link.

## 8. Security checks (Supabase SQL Editor)
You need two test accounts, A and B, both with a phone saved. Copy A's id from Table Editor, `profiles`.

```sql
-- RLS is on for both tables (both rows show true)
select tablename, rowsecurity from pg_tables
where schemaname = 'public' and tablename in ('profiles', 'profile_private');

-- Pretend to be user A, then try to read and change other people's data
begin;
set local role authenticated;
select set_config('request.jwt.claims', '{"sub":"<A-id>","role":"authenticated"}', true);
select user_id, phone from public.profile_private;          -- only A's row
update public.profiles set full_name = 'x' where id <> '<A-id>'; -- UPDATE 0
rollback;

begin;
set local role authenticated;
select set_config('request.jwt.claims', '{"sub":"<A-id>","role":"authenticated"}', true);
update public.profiles set is_admin = true where id = '<A-id>'; -- ERROR: permission denied
rollback;
```
