# F6 test steps: rental requests

Feature: a member sends a request for a live ad (who will live there, how many people, occupation, move-in date, message). The landlord (the ad's poster or a manager of its building) sees it in a requests inbox, shortlists it (the member's phone number is then shared) or declines it with a reason the member sees. The member follows their requests in "My requests" and can withdraw them. Limits: one open request per ad, 10 open requests per member, 20 new requests per member in 24 hours, and no new request to an ad whose landlord declined the member.
Done when (FR21 to FR24): M1 sends a request, N shortlists it and sees M1's phone number, N declines another request with a reason that M1 sees, and M1 withdraws a request, after which N no longer sees the number.

## Before you start
- Run the F6 migration on the dev project once, in Supabase **SQL Editor**: `supabase/migrations/20261030120000_f6_requests.sql`. Running it twice is safe.
- Check that it ran: the query below shows one row where every column is `true`.

```sql
-- Query 0: is the F6 migration applied?
select
  to_regclass('public.rental_requests') is not null                    as rental_requests,
  exists (select 1 from pg_proc where proname = 'send_request'
            and pronamespace = 'public'::regnamespace)                  as send_request,
  exists (select 1 from pg_proc where proname = 'request_inbox'
            and pronamespace = 'public'::regnamespace)                  as request_inbox,
  exists (select 1 from pg_policies where tablename = 'profile_private'
            and policyname = 'landlords read a shortlisted seeker''s phone') as phone_policy;
```

## 10. Privacy (Supabase SQL Editor)
Each query pretends to be someone for a moment. Run each one on its own.

```sql
-- Query 2: a visitor cannot read or send requests (expect: false, false)
set local role anon;
select set_config('request.jwt.claims', '{"role":"anon"}', true);
select
  has_table_privilege('public.rental_requests', 'select') as can_read_requests,
  has_function_privilege('public.send_request(uuid, public.household_type, integer, text, date, text)', 'execute') as can_send;
```

```sql
-- Query 3: a member sees only their own requests and phone (expect: 0, 0). Change the email to M2's.
select set_config('request.jwt.claims', json_build_object('sub', id, 'role', 'authenticated')::text, true)
from auth.users where email = 'housemanagerbd+m2@gmail.com';
set local role authenticated;
select
  (select count(*) from public.rental_requests where tenant_id <> auth.uid()) as others_requests,
  (select count(*) from public.profile_private where user_id <> auth.uid())  as others_phones;
```

```sql
-- Query 4: what landlord N sees. Every request on N's ads; a phone number only
-- for members N has shortlisted (and not after they withdraw or are declined).
select set_config('request.jwt.claims', json_build_object('sub', id, 'role', 'authenticated')::text, true)
from auth.users where email = 'housemanagerbd+n@gmail.com';
set local role authenticated;
select l.title, p.full_name, r.status, pp.phone
from public.rental_requests r
join public.listings l on l.id = r.listing_id
join public.profiles p on p.id = r.tenant_id
left join public.profile_private pp on pp.user_id = r.tenant_id
order by r.created_at;
```

```sql
-- Query 5: an admin cannot answer a request for a landlord (expect: ERROR: not_allowed)
select set_config('request.jwt.claims', json_build_object('sub', id, 'role', 'authenticated')::text, true)
from auth.users where email = 'housemanagerbd+admin1@gmail.com';
set local role authenticated;
select public.decline_request((select id from public.rental_requests order by created_at limit 1), 'other', 'test');
```

## 11. Clean up
```sql
-- Query 6: delete the test accounts' requests and everything they posted
-- (ads, drafts, units, buildings), then reset N. Other accounts are not touched.
delete from public.rental_requests
where tenant_id in (select id from auth.users where email like 'housemanagerbd+%@gmail.com');
delete from public.listings
where posted_by in (select id from auth.users where email like 'housemanagerbd+%@gmail.com');
delete from public.units
where building_id in (select id from public.buildings
  where created_by in (select id from auth.users where email like 'housemanagerbd+%@gmail.com'));
delete from public.buildings
where created_by in (select id from auth.users where email like 'housemanagerbd+%@gmail.com');
update public.profiles set trust_level = 0, is_banned = false
where id in (select id from auth.users where email like 'housemanagerbd+%@gmail.com' and email not like 'housemanagerbd+admin%');
```
Requests on the deleted ads go with them. The test accounts stay for the next feature (F7 uses the same request threads). The photo files stay in N's folder in `listing-photos`; delete them there if you like.
