# F8 test steps: offer and confirm

Feature: on a shortlisted request, the landlord side (the ad's poster or a caretaker of the building) makes an offer: monthly rent, advance, move-in date and an optional note. The member has 48 hours to answer on the request's page. To accept, they share their NID number, a current photo and their permanent address, and tick a consent box. The server encrypts the NID number before saving it, the photo goes to a private storage bucket, and the database creates the tenancy in one transaction. When no place is left, the ad becomes **Rented**, the unit **Rented**, and every other open request on the ad is declined with the reason "The place is no longer available".
Rules: offers only on shortlisted requests, while the ad is live and neither side is suspended. Open offers on one ad never hold more places than the ad has left (1 for a flat, room or sublet; the seats on offer for a mess, where a request takes one seat per person). The landlord side can take an offer back (a decline with a reason); the member can turn it down (a withdrawal). An offer that passes 48 hours expires; the member can then send a new request. The NID details and photo are seen only by the tenant and the landlord side, never by admins.
Done when (FR26 to FR28): with two seekers on one flat, accepting the offer creates one tenancy, marks the ad rented, and declines the other seeker automatically.

## Before you start
- Run the F8 migration on the dev project once, in Supabase **SQL Editor**: `supabase/migrations/20261101120000_f8_offers.sql`. Running it twice is safe. It also creates the private `tenant-docs` bucket and turns on live updates for `rental_requests`.
- Check that it ran: the query below shows one row where every column is `true`.

```sql
-- Query 0: is the F8 migration applied?
select
  to_regclass('public.tenancies') is not null                                  as tenancies,
  to_regclass('public.tenant_verifications') is not null                       as verifications,
  exists (select 1 from pg_proc where proname = 'make_offer'
            and pronamespace = 'public'::regnamespace)                         as make_offer,
  exists (select 1 from pg_proc where proname = 'accept_offer'
            and pronamespace = 'public'::regnamespace)                         as accept_offer,
  exists (select 1 from storage.buckets where id = 'tenant-docs' and not public) as private_bucket,
  exists (select 1 from pg_publication_tables
            where pubname = 'supabase_realtime' and tablename = 'rental_requests') as live_updates;
```

```sql
-- Query 1: M1's open offer on TEST F8 mess seats runs out now (as if 48 hours passed)
update public.rental_requests r
set offer_expires_at = now() - interval '1 minute'
from public.listings l, auth.users u

  and u.id = r.tenant_id and u.email = 'housemanagerbd+m1@gmail.com'
```

## 10. Privacy (Supabase SQL Editor)
Each query pretends to be someone for a moment. Run each one on its own.

```sql
-- Query 2: a visitor cannot read tenancies or NID details, or make or accept offers
-- (expect: false, false, false, false)
select
  has_table_privilege('anon', 'public.tenancies', 'select')                                       as tenancies,
  has_table_privilege('anon', 'public.tenant_verifications', 'select')                            as verifications,
  has_function_privilege('anon', 'public.make_offer(uuid, integer, integer, date, text)', 'execute') as make_offer,
  has_function_privilege('anon', 'public.accept_offer(uuid, text, text, text, text, boolean)', 'execute') as accept_offer;
```

```sql
-- Query 3: an admin sees the tenancies but no NID details (expect: 2, 0)
select set_config('request.jwt.claims', json_build_object('sub', id, 'role', 'authenticated')::text, true)
from auth.users where email = 'housemanagerbd+admin1@gmail.com';
set local role authenticated;
select
  (select count(*) from public.tenancies
    where listing_id in (select id from public.listings where title like 'TEST F8%')) as tenancies,
  (select count(*) from public.tenant_verifications)                               as nid_rows;
```

```sql
-- Query 4: the NID number is stored encrypted; only the last 4 digits are readable
-- (expect: 7890, v1:, false)
select v.nid_last4,
       left(v.nid_encrypted, 3)                    as format,
       v.nid_encrypted like '%1234567890%'         as number_visible
from public.tenant_verifications v
join auth.users u on u.id = v.tenant_id
where u.email = 'housemanagerbd+m1@gmail.com';
```

```sql
-- Query 5: nobody writes tenancies directly, not even the tenant
-- (expect: ERROR: permission denied for table tenancies)
select set_config('request.jwt.claims', json_build_object('sub', id, 'role', 'authenticated')::text, true)
from auth.users where email = 'housemanagerbd+m1@gmail.com';
set local role authenticated;
update public.tenancies set monthly_rent = 1000 where tenant_id = auth.uid();
```

## 11. Clean up
```sql
-- Query 6: delete the test accounts' tenancies first (they protect the ads and
-- units), then their requests (NID rows and messages go with them) and
-- everything they posted, then reset the accounts. Other accounts are not touched.
delete from public.tenancies
where tenant_id in (select id from auth.users where email like 'housemanagerbd+%@gmail.com')
   or landlord_id in (select id from auth.users where email like 'housemanagerbd+%@gmail.com');
delete from public.rental_requests
where tenant_id in (select id from auth.users where email like 'housemanagerbd+%@gmail.com');
delete from public.listings
where posted_by in (select id from auth.users where email like 'housemanagerbd+%@gmail.com');
delete from public.units
where building_id in (select id from public.buildings
  where created_by in (select id from auth.users where email like 'housemanagerbd+%@gmail.com'));
delete from public.buildings
where created_by in (select id from auth.users where email like 'housemanagerbd+%@gmail.com');
update public.profiles set trust_level = 0, is_banned = false
where id in (select id from auth.users where email like 'housemanagerbd+%@gmail.com' and email not like 'housemanagerbd+admin%');
```
