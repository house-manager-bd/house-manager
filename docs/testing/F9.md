# F9 test steps: notifications

Feature: members hear about the steps that need them, in the app and by email. A bell in the header (left of the profile picture) shows how many notifications are unread and updates live. It opens **Notifications**, newest first. Each notification says what happened, in the language you browse in, with the ad's title on its own line; opening one marks it read and goes to its request, the ad, or **My ads**. Every notification is also emailed, in the language saved on the member's profile (the language last chosen with the header's language button while logged in), with a link to the page.
Who hears what: the landlord side (the poster and the building's caretakers) about a new request, an accepted offer and a turned-down offer; the member about being shortlisted, an offer (with its deadline), a decline (also the automatic "no longer available"), and an offer taken back; both sides when an offer expires; the poster when an admin approves, rejects, hides or restores the ad, or three reports hide it. Nobody hears about their own action, and withdrawing a new or shortlisted request tells nobody.
Rules: opening a request's page marks its notifications read. **Mark all as read** clears the rest. Emails can be turned off on the Notifications page; notifications still show in the app. Emails never carry addresses, phone numbers, NID details or free text (notes, rejection reasons), only what happened and a link. An email not sent within 24 hours is dropped.
Done when (FR29): a member sends a request and the landlord's bell shows it at once, the landlord shortlists it and makes an offer, and the member gets both in the app (live) and by email in their own language, with links to the request; opening a notification marks it read, and a member who turns emails off still sees notifications in the app but gets no more emails.

## 8. Privacy (Supabase SQL Editor)
Each query pretends to be someone for a moment. Run each one on its own.

```sql
-- Query 3: visitors read nothing; members cannot change notifications or read the email outbox
-- (expect: false, false, false, false)
select
  has_table_privilege('anon', 'public.notifications', 'select')                 as visitor_reads,
  has_table_privilege('authenticated', 'public.notifications', 'update')        as member_updates,
  has_table_privilege('authenticated', 'public.notification_emails', 'select')  as member_reads_outbox,
  has_function_privilege('anon', 'public.unread_notification_count()', 'execute') as visitor_counts;
```

```sql
-- Query 4: M1 sees only M1's own notifications (expect: two equal numbers, above 0)
select set_config('request.jwt.claims', json_build_object('sub', id, 'role', 'authenticated')::text, true)
from auth.users where email = 'housemanagerbd+m1@gmail.com';
set local role authenticated;
select count(*) as visible, count(*) filter (where user_id = auth.uid()) as own
from public.notifications;
```

```sql
-- Query 5: without the right secret, nobody can take emails from the outbox
-- (expect: ERROR: not_allowed)
set local role anon;
select * from public.claim_notification_emails('a-wrong-secret-that-is-long-enough-0000', 1);
```

delete from public.units

  where created_by in (select id from auth.users where email like 'housemanagerbd+%@gmail.com'));
delete from public.buildings
where created_by in (select id from auth.users where email like 'housemanagerbd+%@gmail.com');
delete from public.notifications

delete from public.notification_settings

update public.profiles set trust_level = 0, is_banned = false
where id in (select id from auth.users where email like 'housemanagerbd+%@gmail.com' and email not like 'housemanagerbd+admin%')
