# F5 test steps: moderation

Feature: automatic checks when an ad is sent in, trust levels (a new member's first ad and every flagged ad wait in a review queue), a report button with an automatic hide at 3 reports, and admin pages at `/admin` (overview, review queue with a Hidden tab, reports, members with ban and unban). Also a minimum photo size.
Done when (PROJECT_PLAN.md section 9): a new member's first ad waits in the queue, an admin approves it, and the member's second ad goes live directly.

## Before you start
- Run the F5 migration on the dev project once, in Supabase **SQL Editor**: `supabase/migrations/20261015120000_f5_moderation.sql`. Running it twice is safe.
- Check that it ran: the query below shows one row where every column is `true`.

```sql
-- Query 0: is the F5 migration applied?
select
  to_regclass('public.reports') is not null              as reports,
  to_regclass('public.moderation_actions') is not null   as moderation_actions,
  to_regclass('public.listing_flags') is not null        as listing_flags,
  to_regclass('public.moderation_words') is not null     as moderation_words,
  exists (select 1 from information_schema.columns
          where table_schema = 'public' and table_name = 'listings'
            and column_name = 'submitted_at')            as submitted_at,
  exists (select 1 from pg_proc where proname = 'moderate_listing'
            and pronamespace = 'public'::regnamespace)   as moderate_listing,
  exists (select 1 from pg_proc where proname = 'compute_listing_flags'
            and pronamespace = 'public'::regnamespace)   as checks;
```

## 12. Privacy (Supabase SQL Editor)
Each query pretends to be someone for a moment and only reads. Run each one on its own.

```sql
-- Query 2: a visitor
set local role anon;
select set_config('request.jwt.claims', '{"role":"anon"}', true);
select
  (select count(*) from public.listings where status <> 'active')   as hidden_ads_seen,    -- 0
  public.is_admin()                                                  as is_admin,          -- false
  has_table_privilege('public.reports', 'select')                    as can_read_reports;  -- false
```

```sql
-- Query 3: a member who is not an admin (change the email to M1's)
select set_config('request.jwt.claims', json_build_object('sub', id, 'role', 'authenticated')::text, true)
from auth.users where email = 'm1@example.com';
set local role authenticated;
select
  (select count(*) from public.listing_flags)                                  as flags_seen,       -- 0
  (select count(*) from public.moderation_actions)                             as actions_seen,     -- 0
  (select count(*) from public.reports where reporter_id <> auth.uid())        as others_reports,   -- 0
  (select count(*) from public.listings where status in ('pending_review', 'hidden', 'rejected')
     and posted_by <> auth.uid())                                              as others_hidden_ads, -- 0
  public.is_admin()                                                            as is_admin;         -- false
```

```sql
-- Query 4: a member cannot use the admin functions (expect: ERROR: not_allowed)
```

## 13. Clean up
```sql
-- Query 6: delete every TEST F5 ad, unit and building, and reset N (change the email)
delete from public.listings where title like 'TEST F5%';
delete from public.units u using public.buildings b where u.building_id = b.id and b.name like 'TEST F5%';
delete from public.buildings where name like 'TEST F5%';
update public.profiles set trust_level = 0, is_banned = false
where id = (select id from auth.users where email = 'n@example.com');
```
Reports and flags go with the ads. The photo files stay in Storage, in N's folder in `listing-photos`; delete that folder there if you like.
