# F2 test steps: properties and posting an ad (text)

Feature: location data, buildings and units ("My properties"), and the six-step post-ad wizard with drafts.
Done when (PROJECT_PLAN.md section 9): a member adds one building with two units, posts a flat ad for one unit, starts a second ad without retyping the address, and sees the advance warning above one month.

## Before you start
- Run the two F2 migrations on the dev project, **in this order**, in Supabase **SQL Editor** (one at a time, each once):
  1. `supabase/migrations/20261005120000_f2_locations.sql`
  2. `supabase/migrations/20261005120100_f2_properties_listings.sql`
- Check in **Table Editor**: `divisions` has 8 rows, `districts` 64, `thanas` 7, `areas` 22. Every new table shows "RLS enabled".
- Log in and switch to **landlord mode** (avatar menu). The menu now shows My properties and My ads.
- Test at 360px wide (Chrome device mode) and on a real phone.

## 6. Privacy and access (Supabase SQL Editor)
Use two accounts, A (owner of Rahman Villa) and B (anyone else).
```sql
-- B cannot see A's buildings that have no live ad, and cannot see drafts
begin;
set local role authenticated;
select set_config('request.jwt.claims', '{"sub":"<B-id>","role":"authenticated"}', true);
select name from public.buildings;          -- only buildings with a live ad
select id, status from public.listings;     -- only live ads, no drafts of A
update public.listings set monthly_rent = 1 where status = 'active';   -- UPDATE 0
rollback;

-- Visitors (not logged in) never see exact addresses or phone numbers
begin;
set local role anon;
select * from public.building_private;      -- ERROR: permission denied
select * from public.listing_private;       -- ERROR: permission denied
rollback;
```
In the app, log in as B and open `/en/dashboard/properties/<A's building id>`: it shows the 404 page.
