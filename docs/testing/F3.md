# F3 test steps: photos and the ad page

Feature: 4 to 8 photos per ad (compressed in the browser, reorder, choose cover), the public ad page with gallery, costs, rules and an approximate area, and the exact address and phone only for logged-in members (phone through a reveal button, 20 ads a day).
Done when (PROJECT_PLAN.md section 9): a logged-out visitor sees the ad without the address, and logs in to see it.

## Before you start
- Run the F3 migration on the dev project once, in Supabase **SQL Editor**: `supabase/migrations/20261006120000_f3_photos_contact.sql`.
- Check: **Table Editor** shows `listing_photos` and `contact_reveals` with "RLS enabled". **Storage** shows a public `listing-photos` bucket.
- You need two accounts: **A** (landlord, owns Rahman Villa from F2) and **B** (any other member). Use a private window for "visitor".
- Have 9 or more photos on your phone or laptop, including one large phone photo (over 3 MB) and one portrait photo.
- Ads published in F2 have no photos. They stay live and their page shows "No photos yet". Editing live ads comes in F10.

The limit counts **different** ads, so query 1 makes 20 throwaway expired ads and logs a reveal of each for B. Run each query on its own, without the ```` ``` ```` lines. Replace `<A-id>` (the poster), `<B-id>` (the member) and `<unit-id>` (any of A's units). Find them with `select id, full_name from public.profiles;` and `select id, unit_id, posted_by from public.listings;`.

```sql
-- Query 1: 20 fake reveals for B
with fake as (
  insert into public.listings (unit_id, posted_by, posted_as, listing_type, status, title)
  select '<unit-id>', '<A-id>', 'owner', 'flat', 'expired', 'TEST reveal limit'
  from generate_series(1, 20)
  returning id
)
insert into public.contact_reveals (user_id, listing_id)
select '<B-id>', id from fake;
```

```sql
-- Query 2: clean up (deleting the fake ads also deletes their reveals)
delete from public.listings where title = 'TEST reveal limit' and status = 'expired';
```

## 8. Privacy and access (Supabase SQL Editor)
Run once on the real project before the demo (like F1.md section 8 and F2.md section 6). Each query pretends to be one kind of user for a moment and only reads, so nothing changes. Run each query on its own and compare every column with the expected value.

```sql
-- Query 1: a visitor (not logged in)
set local role anon;
select set_config('request.jwt.claims', '{"role":"anon"}', true);
select
  has_column_privilege('public.buildings', 'name', 'select')         as can_read_building_name,  -- false
  (select count(*) from public.buildings)                             as buildings_visible,       -- only buildings with a live ad
  has_table_privilege('public.listing_private', 'select')             as can_read_phones,         -- false
  (select count(*) from public.listings where status <> 'active')     as non_live_ads_visible,    -- 0
  (select count(*) from public.listing_photos)                        as photos_visible,          -- photos of live ads only
  has_function_privilege('public.reveal_contact(uuid)', 'execute')    as can_reveal_phone;        -- false
```

Replace `<B-id>` with member B's id (`select id, full_name from public.profiles;`).

```sql
-- Query 2: member B
set local role authenticated;
select set_config('request.jwt.claims', '{"sub":"<B-id>","role":"authenticated"}', true);
select
  (select count(*) from public.listing_private p join public.listings l on l.id = p.listing_id
     where l.posted_by <> auth.uid())                                          as others_phones_readable,      -- 0
  (select count(*) from public.listings
     where status <> 'active' and posted_by <> auth.uid())                     as others_drafts_visible,       -- 0
  (select count(*) from public.listing_photos ph join public.listings l on l.id = ph.listing_id
     where l.status <> 'active' and l.posted_by <> auth.uid())                 as others_draft_photos_visible, -- 0
  (select count(*) from public.building_private)                               as exact_addresses_visible,     -- B's own buildings plus buildings with a live ad
  has_table_privilege('public.listing_photos', 'insert')                       as can_insert_photo_rows,       -- false
  has_function_privilege('public.reveal_contact(uuid)', 'execute')             as can_reveal_phone;            -- true
```
